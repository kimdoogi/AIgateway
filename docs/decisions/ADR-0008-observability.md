# ADR-0008: 관측성·로깅·데이터 주권 — 본문 로깅 기본 on(테넌트 opt-out), 3층 구조, OTel

- 상태: **승인** (2026-08-20 사용자 결정)
- 날짜: 2026-08-20
- 관련: [ADR-0001](ADR-0001-adapter-architecture.md) D7(grounding 제외), [ADR-0006](ADR-0006-state-layer.md)

## 결정

### 1. 로그 3층 구조

| 층 | 내용 | 기본값 |
|---|---|---|
| 메타데이터 로그 | 게이트웨이 request-id, 테넌트/가상 키, 모델·프로바이더·표면, usage/billing 요약, 상태·finishReason, 레이턴시(전체/TTFT), 폴백 이력, warning 목록 — **본문 없음** | 항상 on |
| 본문 로그 | 요청/응답 본문 (IR 형태) | **기본 on, 테넌트 opt-out** (사용자 결정) + 필드 마스킹 옵션 |
| 트레이스/메트릭 | OpenTelemetry — 파이프라인 단계별 span(인바운드 변환→정책→재타게팅→어댑터→프로바이더), OTLP 익스포트 | 항상 on |

### 2. 제외·마스킹 규칙

- **Gemini grounding 메타데이터(searchEntryPoint 포함)는 본문 로그·캐시에서 무조건 제외** (TOS — D7과 동급 규칙).
- 자격증명·베타 헤더 값 등 시크릿은 전 층에서 마스킹.
- 테넌트별 필드 마스킹 규칙(예: PII 패턴) 설정 가능.

### 3. request-id 상관관계

- 게이트웨이가 자체 request-id 발급 → 응답 헤더로 반환.
- 프로바이더 request-id(`request-id`/`x-request-id`)를 IR envelope와 메타 로그에 수납 — 프로바이더 지원 문의 시 추적 가능.

### 4. 보존 기간

- 메타 90일 / 본문 30일 기본, 테넌트 설정으로 조정 가능. 원장(ADR-0007)은 별도(정산 목적, 장기).

### 5. 데이터 주권 (국내 기업 대상 요구)

- 테넌트 정책에 **허용 리전 목록** → 라우팅 트리 제약으로 반영 + 지원 프로바이더에는 `inference_geo` 강제 (Anthropic), 리전 고정 배포 모델(xAI EU 등) 매핑.
- 로그·원장 저장 위치 국내 고정 옵션.

### 6. 컴플라이언스 요구사항 (본문 로깅 기본 on의 대가)

- 테넌트 온보딩 시 본문 로깅 사실·보존 기간·opt-out 방법 고지 필수 (개인정보보호법상 처리방침 반영 사항).
- 테넌트 데이터 삭제 요청 시 본문 로그 일괄 삭제 API (ADR-0006 서버 상태 삭제 대행과 함께).

## 결과

- walking skeleton부터 메타 로그 + OTel 계측을 포함 (나중에 붙이면 계측 공백 발생).
- 본문 로그 파이프라인은 grounding 제외·마스킹 훅과 함께 구현 — 제외 규칙이 없는 채로 본문 로깅을 먼저 켜는 것 금지.
